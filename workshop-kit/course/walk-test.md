# The walk test

The test an attendee's folder must pass at the end of session 5. The facilitator introduces
it in session 4 and runs it in session 5. The test applies to any folder built by the method.
`example/ordered/` passes it. `example/messy/` fails items 1, 2, 4, 5, 6, 8 and 9.

Run the items in order. Each item states the action, the pass evidence and the fail
evidence. Record pass or fail per item. A folder passes the walk test when every item
passes.

## Before you start

1. Close every open conversation.
2. Open a new session with no memory of earlier ones.
3. Point the session at the folder.
4. Do not type anything else yet.

## The items

### 1. Cold start

Ask: "What is this folder, what is in progress, and what is next?"

- Pass: the answer names the folder's purpose, the open work and the next step. The session
  read the map and at most two other files to answer.
- Fail: the answer is a guess, or the session read more than three files, or the answer
  names work that is finished.

### 2. One request routes

Give one real request in one line. Watch the files the session opens.

- Pass: the session opens three files or fewer. Each one is named in the map's routing
  table for this kind of request.
- Fail: the session opens a file the map does not name for this request, or it opens the
  archive, or it asks where to look.

### 3. The output is a file

Let the session finish the request.

- Pass: the result is a file in the folder the map names for this kind of output. You can
  open it, edit it and save it before anything else happens.
- Fail: the result exists only in the conversation, or it landed in a folder the map does
  not name.

### 4. One home per fact

Choose one fact that changes: a price, an opening hour, a deadline. Search the folder for it.

- Pass: the fact appears in one file. Every other mention points to that file.
- Fail: the fact appears in two files with two values, or in two files with the same value.

### 5. Every rule carries its why and its date

Open the map and every contract. Read each rule.

- Pass: each rule states why it exists and the date it was set.
- Fail: one rule has no why. Delete it or give it one before you continue.

### 6. Every stage has a contract

Open each stage folder.

- Pass: each stage folder holds a contract with four parts: what it reads, what it does,
  what it writes, who checks it. The output of one stage is named as the input of the next.
- Fail: a stage folder has no contract, or a contract has no "who checks it" part, or two
  stages write to the same output.

### 7. The gate is human

Find the point where a person checks before the next stage runs.

- Pass: the check is a line a person reads and a box a person ticks. The session was never
  told to tick it. For an action that sends, deletes or spends, a setting or a hook stops
  the session as well, not only a line in the map.
- Fail: the session advanced past the check on its own, or the check exists only as a line
  in the map for an action that sends, deletes or spends.

### 8. No script drives the stages

List every script in the folder. Read what each one does.

- Pass: each script does one exact step and stops. It has one input and one output. No
  script runs one stage and then starts the next.
- Fail: a script sequences two or more stages, or a script decides which stage runs next.

### 9. The archive is marked

Find the folder for old work.

- Pass: the map names it and says it is never read. Item 2 confirmed the session did not
  open it.
- Fail: there is no archive and old versions sit beside current ones, or the archive exists
  and the map does not say it is never read.

### 10. A stranger can do the job with the assistant off

Hand the folder to another attendee. Switch the assistant off. Ask them to do one request
from the map alone.

- Pass: they find the inputs, the process and the output location from the map and the
  contracts, and they produce the output by hand.
- Fail: they ask you a question that the map could have answered. Write the answer into the
  map and run item 10 again.

### 11. The model swaps

Point a different model or a different tool at the same folder. If the tool reads a
different map file name, copy the map to that name. Repeat item 2 with the same request.

- Pass: the session opens the same files and writes to the same place. The only change you
  made was the name of the map file.
- Fail: you had to change a contract or a rule for the new tool to behave.
